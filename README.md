# DALA COFFEE

Одностраничный сайт вымышленной кофейни в Астане: меню с фильтрами по категориям,
корзина, адреса с картой, форма обратной связи. Два языка — русский и казахский,
переключаются без перезагрузки страницы.

Кофейни не существует, адреса, телефон и почта выдуманы: проект учебный.

**Что внутри:** [Vite](https://vite.dev) как сборщик, [Tailwind CSS v4](https://tailwindcss.com)
для стилей, обычный JavaScript без фреймворков. Бэкенда нет — корзина живёт
в браузере, форма ничего никуда не отправляет.

---

## Как запустить у себя

Нужен [Node.js](https://nodejs.org) версии 20 или новее. Проверить, установлен ли он:

```bash
node -v
```

Если версия вывелась — всё в порядке. Дальше в папке проекта:

```bash
npm install     # скачать зависимости, делается один раз
npm run dev     # запустить сайт для разработки
```

В терминале появится адрес вроде `http://localhost:5173` — откройте его в браузере.
Пока команда `npm run dev` работает, любая правка в файлах сразу видна на странице,
перезагружать вручную не нужно. Остановить — `Ctrl + C` в терминале.

Два файла, которые нужны чаще всего, — `src/data/menu.js` и `src/data/locale.js`.
Всё остальное можно не трогать.

Разметка повторяющихся элементов лежит в `<template data-template="…">`
в `index.html`, а не в JS-строках: классы остаются там, где их видит Tailwind,
а заполняется всё через `textContent`.

## Как добавить напиток

Откройте `src/data/menu.js` и допишите строку в список `menu`:

```js
{ id: 'raf-halva', category: 'author', name: { ru: 'Раф халва', kk: 'Халва рафы' }, desc: { ru: 'Сливочный, с халвой', kk: 'Халвасы бар кілегейлі' }, price: 2100 },
```

Что означают поля:

| поле | что писать |
| --- | --- |
| `id` | латиницей, без пробелов, ни у кого больше такого нет |
| `category` | одна из: `classic`, `milk`, `ice`, `author`, `sweet` |
| `name` / `desc` | название и описание на двух языках |
| `price` | число в тенге, без пробелов и знака ₸ |
| `oldPrice` | (необязательно) старая цена — покажется зачёркнутой |
| `badge` | (необязательно) плашка на карточке, например `'−15%'` |

Сохраните файл — напиток появится на странице сам. Цену форматирует сайт:
`2100` превратится в «2 100 ₸».

Категории задаются в том же файле, в списке `categories` выше.

## Как поменять текст на сайте

Все надписи — в `src/data/locale.js`, каждая на двух языках рядом:

```js
menuSection: {
  title: 'Меню',
  lead: 'Варим на своём зерне. Любую позицию можно взять с собой.',
},
```

Если добавляете новый ключ — добавьте его **в обе ветки**, `ru` и `kk`. Если
казахского перевода не будет, на его месте покажется русский текст.

## Фотографии

Всё, что лежит в `public/`, отдаётся с корня сайта: `public/images/hero.jpg`
доступен как `/images/hero.jpg`.

| файл | пропорции | размер | где виден |
| --- | --- | --- | --- |
| `images/hero.jpg` | 4:3 на мобильном, 4:5 на десктопе | 1200 × 1500 px | первый экран |
| `images/about.jpg` | 4:3 на мобильном, 1:1 на десктопе | 1000 × 1000 px | блок «О нас» |

Кадрируйте под пропорции десктопа — на узких экранах картинка обрежется
по центру через `object-fit: cover`.

Формат — JPEG (или WebP, если не нужна поддержка совсем старых браузеров),
вес до ~300 КБ: сайт статический, оптимизации на лету не будет. Сжать можно
на [squoosh.app](https://squoosh.app).

Пока файла нет, контейнер остаётся с мягкой заливкой: у `<img>` стоит `onerror`,
который прячет битую картинку, и вёрстка не ломается. Отдельной заглушки
в репозитории нет намеренно — так сразу видно, что фото ещё не положили.

Если меняете пропорции, поправьте `width` и `height` у тега `<img>`
в `index.html`: они нужны, чтобы страница не «прыгала» при загрузке.

## Сборка готовой версии

```bash
npm run build     # собрать сайт в папку dist/
npm run preview   # посмотреть собранное локально
```

В папке `dist/` окажется готовый сайт — обычные HTML, CSS и JS. Его можно
положить на любой хостинг, никакого сервера и базы данных не нужно.

## Как выложить в интернет бесплатно

### Netlify — проще

1. Залейте проект на GitHub.
2. Зарегистрируйтесь на [netlify.com](https://netlify.com) через GitHub.
3. **Add new site → Import an existing project**, выберите репозиторий.
4. Netlify спросит настройки — впишите:
   - **Build command:** `npm run build`
   - **Publish directory:** `dist`
5. Нажмите **Deploy**. Через минуту сайт будет по адресу вида
   `имя-сайта.netlify.app`; имя можно поменять в настройках.

Дальше каждый `git push` пересобирает сайт автоматически.

### GitHub Pages

**Важно:** если сайт будет жить по адресу `имя.github.io/coffee-shop/`,
сначала откройте `vite.config.js` и допишите строку `base` — иначе стили
и скрипты не найдутся:

```js
export default defineConfig({
  base: '/coffee-shop/',   // ← имя вашего репозитория со слэшами
  plugins: [tailwindcss()],
  // …
});
```

Затем создайте файл `.github/workflows/deploy.yml`:

```yaml
name: Deploy to GitHub Pages
on:
  push:
    branches: [main]
permissions:
  contents: read
  pages: write
  id-token: write
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci
      - run: npm run build
      - uses: actions/upload-pages-artifact@v3
        with:
          path: dist
  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
    steps:
      - uses: actions/deploy-pages@v4
```

Загрузите изменения на GitHub, затем в репозитории откройте
**Settings → Pages** и в разделе **Source** выберите **GitHub Actions**.
После следующего `git push` сайт появится по адресу
`https://ваш-логин.github.io/coffee-shop/`.

# Подробности для тех, кто будет править код

## Локализация

Языки: `ru` (по умолчанию) и `kk`. Приоритет определения — `?lang=` в URL,
затем `localStorage`, затем `ru`.

Тексты в разметку не пишутся, всё идёт через словарь `src/data/locale.js`:

```html
<h1 data-i18n="hero.title">Кофе в центре степи</h1>
<meta name="description" data-i18n-content="meta.description" content="…" />
<button data-i18n-aria-label="a11y.openMenu">…</button>
```

`data-i18n` подменяет текст элемента, `data-i18n-<атрибут>` — соответствующий атрибут.
Текст внутри HTML остаётся русским вариантом: он виден, если JS не загрузился.

`data-i18n` затирает всё содержимое элемента. Если внутри ссылки есть иконка
или скрытая подпись, переводимый текст выносят в отдельный `<span>` —
иначе перевод снесёт `<svg>` вместе с текстом.

Смена языка не перезагружает страницу и не сбрасывает скролл. Модулям, которые
рисуют контент из JS, нужно подписаться на событие:

```js
import { onLangChange, translateTree } from './i18n.js';

onLangChange(() => renderMenu());   // перерисовать свой блок
translateTree(newlyInsertedNode);   // перевести только что вставленную разметку
```

Публичная `t(key, vars)` языка не принимает: язык знает только внутренняя
`translate()`. Сообщения об ошибках формы хранятся ключами, а не строками, —
иначе при переключении языка на экране остались бы русские фразы.

## Корзина

Бэкенда нет, оформления заказа нет. Состояние лежит в `localStorage` под ключом
`dala:cart` и содержит **только id и количество**:

```json
[{ "id": "latte", "qty": 2 }]
```

Названия и цены туда не попадают намеренно: сохранённое название застряло бы
на языке, выбранном в момент добавления, а сохранённая цена — на старой
стоимости. При отрисовке и то, и другое берётся из `src/data/menu.js` по id.

Хранилище читается с недоверием (`readStorage` в `src/cart.js`): позиции,
которых больше нет в меню, дубликаты, отрицательные и нечисловые количества
отсеиваются, и нормализованный вид сразу записывается обратно.

## Карта

Карта — iframe с OpenStreetMap, под ним лежит блок с адресами. По событию
`load` фрейма показывать карту нельзя: у кросс-доменного iframe оно срабатывает
и на странице ошибки браузера, и вместо запасного блока посетитель видел бы
серую заглушку. Поэтому `src/ui/map.js` сначала проверяет отдельным запросом,
отвечает ли хост, и только потом проявляет карту.

## Дизайн-система

Токены объявлены в `src/styles.css` в блоке `@theme static` и доступны и как
CSS-переменные (`var(--color-caramel)`), и как утилиты Tailwind (`bg-caramel`).

Палитра и шкала кеглей закрыты: дефолтные наборы Tailwind сброшены через
`--color-*: initial` и `--text-*: initial`. Утилит вроде `bg-blue-500` или
`text-6xl` в проекте не существует — случайно вынести цвет за палитру нельзя.

Цвета: `espresso`, `milk`, `caramel`, `cocoa`, `blush`, `stone`, `white`, `alert`.
Правила применения — в комментариях рядом с токенами. Главные из них:

- **сплошная заливка под белым текстом — только `--espresso` или `--cocoa`,
  никогда `--caramel`** (белое на нём даёт 4.08:1 при норме 4.5:1);
- **мелкий текст — только `--espresso` (можно с прозрачностью) или `--cocoa`.**
  На фоне milk `caramel` даёт 3.66:1, `stone` — 3.95:1, оба ниже нормы.
  За `caramel` остаются крупные цены от 28px, за `stone` — только бордеры
  и разделители. Второстепенный текст — `text-espresso/75`, это 6.5:1.

Кегли: `text-caption` 12, `text-small` 14, `text-body` 16, `text-lead` 20,
`text-h3` 28, `text-h2` 40, `text-h1` 64.

Шрифты: Unbounded (заголовки, 600/700) и Inter (текст, 400/500), подключены
с Google Fonts с `display=swap`. Оба покрывают кириллицу и казахские
ә ғ қ ң ө ұ ү һ і.

Минимальная цель для пальца — 44×44 у всех кнопок и иконок-ссылок.

Полный свод правил, включая доступность и порядок проверок перед сдачей, —
в `CLAUDE.md`.
